# Quality checklist

AI-generated ("vibe-coded") front ends tend to fail in the same ways: they look right in a screenshot but are inconsistent, inaccessible, untyped and impossible to maintain. This checklist names those failures and records how this product prevents each one: through an automated gate, a review step or a design-system rule. The last column says what the audit on 13 November 2026 found and fixed.

Run everything automated with `npm run check`. CI runs the same gate on every push and pull request (`.github/workflows/check.yml`).

## Design system and visual consistency

| Typical failure                                                           | How it is prevented here                                                                                                                                     | Audit result                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Hard-coded colours, pixel values, one-off spacing                         | `ds:check` rejects raw hex, px and rem in every source file; only `var(--eu-*)` tokens from Figma                                                            | Clean on all 26 files. One false positive (a ticket number read as a colour) was reworded                                                                                                                                                                                                                                                                        |
| Hand-made buttons, inputs and dialogs that look almost like the real ones | `ds:check` rejects raw `<button>`, `<input>`, `<dialog>` and headings; UI comes from `@euvino/ds` only                                                       | Clean                                                                                                                                                                                                                                                                                                                                                            |
| Components drifting from the design file                                  | Each component is measured in code and in Figma (height, padding, gap, radius, type, icon)                                                                   | Differences found and fixed on the side that was wrong. Code: Button icons, Alert, Empty State, Avatar Giant, breadcrumb chevron, Popover, Top Nav weights, Person Chip, Segmented Control, small-button label, split-button chevron. Figma: Input and Dropdown Medium (38), Filter Tabs, Top Nav spacing, Close Button small, Dropdown options as in production |
| The same UI rebuilt several times                                         | Repeated patterns become design-system components first (`PeopleList`, `FileChip`, `InlineList`, `Combobox`) and are listed in the agent rules (`AGENTS.md`) | Three duplicated people lists merged into one rule (`views/shared/people.tsx`)                                                                                                                                                                                                                                                                                   |
| Separators, dots and glyphs typed into strings                            | `InlineList` draws the divider; strings carry only facts                                                                                                     | All visible dot separators replaced                                                                                                                                                                                                                                                                                                                              |
| Docs that say one thing while the code does another                       | Component docs are generated from the source; size docs checked against rendered sizes                                                                       | Wrong sizes in Button, Segmented Control, Avatar and Input docs corrected                                                                                                                                                                                                                                                                                        |
| Undocumented components                                                   | Every component has a Storybook story generated from typed specs                                                                                             | 22 missing stories added (87 in total)                                                                                                                                                                                                                                                                                                                           |

## Accessibility

| Typical failure                                 | How it is prevented here                                                                                        | Audit result                                                                          |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| Unlabelled icon buttons and fields              | `IconButton` requires `label`; fields require `label`; jsx-a11y lint                                            | axe-core: 0 violations on lists, organisation page, drawer and planner                |
| Clickable `div`s that the keyboard cannot reach | jsx-a11y lint; every remaining exception carries a written reason (listbox options use `aria-activedescendant`) | 23 lint findings reviewed: two fixed, the rest are correct ARIA patterns with reasons |
| Colour as the only cue                          | Links inside text are underlined; status always has an icon or text                                             | Fixed for names in card meta rows (WCAG 1.4.1)                                        |
| Name mismatch for screen readers                | Accessible names come from visible text                                                                         | User menu fixed (WCAG 2.5.3)                                                          |
| Hover-only interactions                         | "+N" lists open on hover, click and Enter                                                                       | Verified                                                                              |
| No confirmation for destructive actions         | `ConfirmDialog tone="danger"`, focus starts on Cancel                                                           | Verified for deleting notes                                                           |
| Same page title everywhere                      | Each route sets its own title                                                                                   | Fixed                                                                                 |

## Code quality

| Typical failure                    | How it is prevented here                                                                                   | Audit result                                                                                                  |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `any`, `@ts-ignore`, unchecked `!` | TypeScript strict, `typescript-eslint` strict                                                              | Three non-null assertions replaced with checks; story generator typed                                         |
| Dead code and unused imports       | `noUnusedLocals`, `noUnusedParameters`, unused-disable reporting                                           | Clean                                                                                                         |
| Silenced lint rules                | Every `eslint-disable` must name the rule and give a reason; unused ones fail the build                    | Four hook-dependency exceptions documented                                                                    |
| Hook misuse                        | `react-hooks` rules                                                                                        | Hooks moved out of story render functions into components                                                     |
| Index keys on editable lists       | Lint review                                                                                                | Contact phone and e-mail rows now have stable ids                                                             |
| God files                          | Split by responsibility: `views/list`, `views/shared`, `views/timeline`, `views/scheduling`, `data`, `lib` | `App.tsx` split                                                                                               |
| Inconsistent formatting            | Prettier and EditorConfig, checked in CI                                                                   | Both repos formatted                                                                                          |
| No tests                           | Vitest + Testing Library for data rules and card behaviour                                                 | App 10 tests, design system 34                                                                                |
| Generated files edited by hand     | Generators own them; `check` fails when they drift                                                         | Token generator fixed: 10 duplicate and self-referencing variables removed, all 498 values verified unchanged |

## Product behaviour

| Typical failure                   | How it is prevented here                                                                                     | Audit result                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------- |
| Buttons and links that do nothing | Placeholder features say "folgt in einer späteren Version"; real actions use `tel:`, `mailto:` and downloads | 13 dead `#` links and 5 no-op menu items replaced |
| Crashes show a blank page         | Root `ErrorBoundary` with a reload action                                                                    | Added                                             |
| Broken layout on small screens    | Header, breadcrumb, tabs, filters, titles and cards shrink or scroll within themselves                       | No horizontal page scroll at 375px                |
| Mixed languages                   | All UI copy and accessible names in German; design-system defaults overridden                                | No English found in UI or labels                  |
| Console noise                     | Checked in a fresh tab                                                                                       | No errors or warnings                             |

## Known limits (demo)

- Contacts, organisations and history are demo data; downloads save a placeholder file.
- Reply, Weiterleiten, profiles and some list actions are announced as coming later.
- Contact photos are sample portraits loaded from randomuser.me.
